# Ocean Fresh 无硬件接入版运行说明

## 1. 先看这里

本文档对应分支：

```text
codex/offline-delivery
```

本版本用于源码检查和离线图片推理演示，不包含 Techik 探测器、现场串口、X 光源、传送带和真实剔除设备接入。

正常使用只分两步：

1. 第一次使用：双击 `setup-environment.cmd`，准备环境并构建软件；
2. 以后启动：双击 `start-oceanfresh.cmd`。

不需要分别打开三个终端，也不需要手工启动数据库、LocalApi 或 YOLO 服务。WPF 主程序会自动启动 LocalApi 和 YOLO 服务；SQLite 数据库会在首次运行时自动创建。

## 2. 第一次使用前准备

### 2.1 系统要求

- Windows 10 或 Windows 11，64 位；
- .NET 8 SDK x64；
- Python 3.11 x64；
- Git；
- Microsoft Visual C++ 2015–2022 Redistributable x64；
- 首次安装依赖时能够访问互联网；
- 建议至少保留 10 GB 可用磁盘空间。

安装脚本会在开始前检查仓库所在磁盘；少于 5 GB 时会停止，避免依赖下载或构建过程中占满磁盘。

NVIDIA 显卡不是必需的。安装脚本检测到 `nvidia-smi` 时会安装 CUDA 11.8 版 PyTorch，否则自动安装 CPU 版；CPU 也能演示，但推理速度较慢。

主交付界面是 WPF，不需要安装 Node.js、npm、MySQL、SQL Server、CUDA Toolkit 或单独的 SQLite。

### 2.2 获取代码

首次克隆：

```powershell
git clone -b codex/offline-delivery --single-branch https://github.com/liuyang-cpu/Ocean-Fresh-Sorting-System-Front-and-Back-End.git
cd "Ocean-Fresh-Sorting-System-Front-and-Back-End"
```

如果仓库是私有仓库，需要先获得访问权限。

已经克隆过仓库时：

```powershell
git fetch origin
git switch codex/offline-delivery
git pull --ff-only origin codex/offline-delivery
```

### 2.3 一键准备环境

在仓库根目录双击：

```text
setup-environment.cmd
```

脚本会自动完成：

1. 检查磁盘空间和 .NET 8 SDK；
2. 将安装临时文件、pip 缓存和 NuGet 缓存放到仓库所在磁盘的 `.setup-cache`，避免占满系统盘；
3. 创建 `.venv` Python 虚拟环境；
4. 安装 PyTorch、Ultralytics、FastAPI 等推理依赖；
5. 还原 NuGet 包；
6. 以 Release 模式构建整个解决方案。

首次运行需要下载较大的 PyTorch 和 NuGet 依赖，耗时取决于网络速度。看到下面的提示即表示成功：

```text
Environment setup completed successfully.
You can now double-click start-oceanfresh.cmd.
```

如果希望即使有 NVIDIA 显卡也强制使用 CPU 环境，可以在命令行执行：

```powershell
.\setup-environment.cmd cpu
```

## 3. 启动软件

环境准备成功后，在仓库根目录双击：

```text
start-oceanfresh.cmd
```

它只负责启动 WPF 主程序。主程序会在后台自动启动：

- LocalApi：`http://127.0.0.1:5188`；
- YOLO 服务：`http://127.0.0.1:8010`。

日常启动不需要再次运行 `setup-environment.cmd`，除非更换电脑、删除了 `.venv`、更新了依赖或清理了构建目录。

## 4. 登录

- 操作员：直接点击“操作员登录”，不需要密码；
- 管理员：默认密码为 `admin123`。

管理员可以配置产品、模型、通道、用户和软件参数。

## 5. 第一次配置离线推理

### 5.1 创建产品

1. 使用管理员账号登录；
2. 打开“设置 → 产品管理”；
3. 新建产品；
4. 通过文件选择窗口导入对应的 `classes.txt`；
5. 设置正常类别和异常类别；
6. 保存。

类别文件位于：

```text
deployment-assets\yolo\youge\classes.txt
deployment-assets\yolo\meibei\classes.txt
deployment-assets\yolo\huage\classes.txt
```

### 5.2 导入模型

1. 打开“设置 → 模型管理”；
2. 点击选择文件；
3. 油蛤演示选择 `deployment-assets\yolo\youge\best.pt`；
4. 绑定刚创建的产品；
5. 填写训练图像尺寸，例如 `640`；
6. 保存。

正常使用完全通过软件界面选择模型，不需要运行 Python 命令。仓库目前只提供油蛤权重；花蛤和美贝需要另行提供对应权重。

### 5.3 创建通道

1. 打开“设置 → 通道配置”；
2. 新建或编辑通道；
3. 选择产品和模型；
4. 设置置信度阈值；
5. 启用通道并保存。

至少需要一个已启用且绑定有效模型的通道。

### 5.4 下载并选择离线图片

完整数据集下载说明位于：

```text
deployment-assets\offline-samples\README.md
```

永久分享地址：<https://pan.quark.cn/s/0ba0afff8173>，没有提取码。

下载并解压后：

1. 回到“主控工作台”；
2. 将数据源切换为“离线图片”；
3. 选择一个直接包含图片的目录，例如 `数据集\youge\normal`；
4. 点击开始检测；
5. 查看图片、检测框、类别、置信度和统计结果。

程序当前读取所选目录第一层的 PNG、JPG、JPEG 和 BMP 文件，不递归读取子目录。因此不要直接选择 `youge` 根目录，应选择它下面的类别目录，或先把多个类别的图片复制到同一个目录。

离线模式只执行推理、记录和统计，不会控制现场硬件，也不会发送真实剔除命令。

## 6. 数据库和运行数据

系统使用 SQLite，首次启动时自动初始化，不需要手工安装或创建数据库。

默认数据目录：

```text
%LOCALAPPDATA%\OceanFreshSortingSystem
```

数据库文件：

```text
%LOCALAPPDATA%\OceanFreshSortingSystem\oceanfresh.db
```

删除该数据库会清空软件配置、检测记录和用户数据，不要把它提交到 Git。

## 7. 更新代码后的处理

一般更新只需要：

```powershell
git pull --ff-only
```

如果更新包含依赖或项目文件变化，再双击一次 `setup-environment.cmd`。普通源码更新也可以直接重新运行该脚本，它会复用现有 `.venv`。

## 8. 常见问题

### 8.1 提示缺少 .NET 8 SDK

安装 .NET 8 SDK x64，而不是只安装普通运行时，然后重新运行 `setup-environment.cmd`。

### 8.2 提示找不到 Python 3.11

安装 Python 3.11 x64，并勾选“Add Python to PATH”。重新打开命令窗口后再次运行安装脚本。

### 8.3 Python 依赖安装失败

首次安装必须联网。检查代理、网络和磁盘空间，然后重新运行安装脚本。已经成功下载的内容通常会被缓存。

如果提示磁盘空间不足，请先确保仓库所在磁盘至少有 5 GB 可用空间，建议预留 10 GB。

### 8.4 软件启动后无法推理

依次检查：

1. 产品是否已导入正确的 `classes.txt`；
2. 模型是否通过界面选择并保存；
3. 通道是否绑定产品和模型并已启用；
4. 图片目录是否直接包含受支持的图片；
5. `8010` 端口是否被其他程序占用。

只有在排查服务时才需要手工访问：

```text
http://127.0.0.1:8010/health
http://127.0.0.1:5188/api/runtime/snapshot
```

### 8.5 GPU 不可用

执行 `nvidia-smi`。如果 Windows 无法识别显卡，请先安装匹配的 NVIDIA 驱动。没有显卡时可以重新运行：

```powershell
.\setup-environment.cmd cpu
```

### 8.6 需要查看详细启动错误

正常用户不需要分别启动服务。只有一键启动失败时，开发者才可在三个终端中分别执行：

```powershell
predict\yolo\service\start_yolo_service.bat
```

```powershell
dotnet run --project src\OceanFresh.SortingSystem.LocalApi
```

```powershell
dotnet run --project src\OceanFresh.SortingSystem.HMI
```

这种方式用于观察错误输出，不是日常启动步骤。

## 9. 验收检查

1. `setup-environment.cmd` 首次执行成功；
2. 双击 `start-oceanfresh.cmd` 能进入登录页面；
3. 操作员和管理员可以登录；
4. 产品、模型和通道可以通过界面完成配置；
5. 能选择本地图片目录并开始推理；
6. 主页面显示图片、检测框、类别和置信度；
7. 数据中心能够查询检测记录和统计信息；
8. 关闭软件后再次双击启动脚本仍能正常运行。
